# 모듈 편성 화면 개편 계획

> **완료된 작업의 기록.** 다섯 자리·초기 두 자리·안드로메다 연구 해금·모듈 다섯 종은
> 2026-09-07에 승인·구현됐다. 아래 승인 대기·코드 변경 문구는 당시 계획이며 재작업 지시가 아니다.
> 현재 값과 동작은 [모듈 상세 기준](design-details.md#m31과-모듈), 당시 사용자 답변은
> [설계 원문](history/design-through-2026-09-07.md#현재-게임-한눈에-보기)을 본다.

현행 `module_popup.gd`의 2×2 상자 배치를 **고리 하나에 자리 다섯**을 둔 편성
화면으로 교체한다. 이 문서는 구현 지시서이며 설계 승인 근거를 대신하지 않는다.
아래 세 질문은 후속 사용자 답변으로 확정됐고, 대체 승인은 설계 문서에 기록했다.

목업: `build/module-loadout-mockup/`의 세 파일을 브라우저로 연다.

| 파일 | 내용 |
|---|---|
| `RingFinal.dc.html` | 확정 화면. 고리·자리·보관함·툴팁 |
| `RingStates.dc.html` | 호버 세 가지와 열린 자리를 다 채운 상태 |
| `RingSpec.dc.html` | 좌표·상태·조작·모션 요약 |

## 승인 기록 (2026-09-07 후속 답변 반영)

최대 5자리·초기 2자리, 안드로메다 연구로 추가 자리 개방, 전체 확장 시 총 5종의
모듈 구성을 사용자에게 확인했다. 구체적인 구현 구성과 이전 승인 대체 기록은
[설계 원문](history/design-through-2026-09-07.md#현재-게임-한눈에-보기)의 모듈 고리 편성 항목에 보존했다. 아래는 질문 당시의 쟁점이다.

### 질문 당시 승인 대기 항목

구현 전에 사용자 결정을 받고 [설계 문서](design.md)에 대체 승인으로 기록한다.
에이전트가 임의로 설계 문서를 고쳐 정합성을 만들지 않는다.

1. **자리 5개.** 2026-09-06 승인은 슬롯 2개다. 다섯 자리는 그 결정을 대체한다.
2. **잠긴 자리를 여는 조건.** 정해진 바 없다. 화면에 잠금을 보여 주는 순간
   플레이어는 여는 방법을 찾는다.
3. **모듈 종류 확장 순서.** 열린 자리 2개에 모듈 2종이면 다 꽂으면 끝이라
   고를 것이 없다. 자리가 열리는 속도보다 모듈 종류가 먼저 늘어야 한다.

## 화면

좌표는 1920×1080 스펙 프레임 기준이다. `UITheme.px()` / `UITheme.size_px()`가
×0.6으로 줄인다. 새 색·새 서체·새 시간값을 만들지 않는다.

### 기하

| 항목 | 값 |
|---|---|
| 고리 | `r 180`, 1px, `INK_MID` 42% |
| 자리 배치 | 5개, 72° 간격, −90°(맨 위)에서 시계 방향 |
| 자리 | `r 38` |
| 커서 표식 | `r 16` + 중심점 `r 2.2` + 4방 눈금, `INSTRUMENT_ARC` |
| 보관함 타일 | 120 × 120 |
| 타일 격자 | 4열, 간격 18 |
| 툴팁 | 폭 400, 기존 성도 툴팁 양식 재사용 |

### 자리 상태 셋

| 상태 | 표현 |
|---|---|
| 장착 | 채움 `#0A0806`, 테두리 `ACCENT_LINE` 90%, 기호 `#FFE8CE` |
| 열림 · 빈 | 파선 테두리 `ACCENT_LINE` 55%, 중앙 십자 `#7D6A5E` |
| 잠김 | 테두리 `#3F3832`, 자물쇠 `#4A4038`, 입력 없음 |

자리 1은 맨 위다. 어디부터 세는지가 화면에서 자명해야 한다.

### 보관함

구매한 모듈을 타일로 늘어놓는다. 이미 꽂힌 모듈도 목록에서 지우지 않고
어둡게 두고 표식을 단다. 무엇을 가졌고 어디에 꽂혔는지가 한 곳에서 읽혀야 한다.

### 조작

- 보관함 타일을 누르면 **시계 방향 첫 빈 열린 자리**에 꽂힌다.
- 고리에 꽂힌 모듈을 누르면 빠져서 보관함으로 돌아온다.
- 잠긴 자리는 입력을 받지 않는다. 호버 툴팁만 뜬다.
- 이미 꽂힌 모듈의 타일을 누르면 무시한다.
- 빈 열린 자리가 없으면 무시하고 툴팁이 사유를 말한다.
- 같은 모듈을 두 자리에 넣지 못한다. `equip()`의 기존 규칙을 유지한다.
- `Esc`로 닫고, 열기 전 일시정지 상태를 복원한다.
- 드래그는 넣지 않는다. 폐기된 작업대의 잔재다.

### 툴팁과 모션

- 툴팁은 이름 · 코드 · 효과 · 조합 · 동작 한 줄로 끝낸다. 마지막 줄은 항상
  지금 누르면 무슨 일이 일어나는지다.
- 커서 옆에 띄우고 화면 밖으로 나가면 반대편으로 뒤집는다. 성도 툴팁과 같은 규칙이다.
- 장착·해제는 0.28초. 기호 페이드와 테두리 밝기 전환뿐이다. 설계 문서의
  연구 설치 연출과 같은 값을 쓴다.
- 섬광도 흔들림도 없다.

## 코드 변경

- `scripts/observation_modules.gd` — `equipped` / `secondary` 두 필드로는 다섯
  자리를 담을 수 없다. `slots: Array[String]`(길이 5)로 바꾸고 `equip()`의 슬롯
  범위를 `0..4`로 넓힌다. `get_save_data()` / `load_save_data()`의 배열 길이도
  함께 바꾼다. 옛 저장의 `[equipped, secondary]`는 앞 두 자리로 복원하고
  나머지는 빈 칸으로 둔다. 열린 자리 수도 저장한다.
- `scripts/module_popup.gd` — 전면 교체. 상자·`×` 닫기 버튼·`›` `◇` 기호는 버린다.
- `scripts/module_visual.gd` — 기존 관측 기호를 그대로 쓴다. 새 도형을 만들지 않는다.
- `scripts/deep_sky_chart.gd` — 진입점은 그대로 둔다.

`observation_modules.gd`의 두 필드에는 최근 조회 캐시가 붙어 있다. 그 작업이
커밋된 뒤에 그 위에서 고친다.

## 유지할 계약

- 가격과 구매는 성도에 남는다. 팝업에 가격·구매·시험 시야를 넣지 않는다.
- 조합값 속도 ×1.35 · 반경 ×1.65 · 동시 3.
- 색은 `scripts/ui_theme.gd` 상수만 쓴다.
- 하늘과 천체는 제 색을 지키고 계기와 인터페이스만 관측소 적색광을 쓴다.
  살아 있는 커서 관측 게이지만 중립 백색이다.
