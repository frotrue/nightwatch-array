# 고정 틱과 천체별 출현

2026-09-11 사용자 승인: GPT-6 Pro 설계를 받은 뒤 게임 내부를 고정 틱으로
변경하고, 자연 천체마다 독립적인 출현 확률을 적용한다. 연구 설명과 관련
효과는 조정하되 별자리 배치·연구 ID·보유 기록·조작·천체 그림은 유지한다.

## 실행 계약

- `Game._physics_process` 한 곳에서 초당 **60회** 실행한다. 설정 화면에서
  틱률을 바꾸지 않는다. 렌더링 FPS 제한/VSync는 시뮬레이션 속도를 바꾸지 않는다.
- 순서: 기존 효과 타이머 → 입력 소비 → 이벤트/출현 → 이동 → 안테나/수동 관측
  → 자동 관측 → 생성 순서대로 완료/소멸 확정 → 라운드 시계 → 저장.
- 완료와 수명 종료가 같은 틱이면 완료가 우선한다. 완료로 생긴 파편은 다음
  틱부터 관측된다. 라운드 마지막 틱 보상은 해당 라운드에 포함한다.
- 히트스톱은 엔진 전체 배속을 바꾸지 않는다. 일반 천체 이동·관측과 안테나만
  0.06배가 되며 라운드·출현·콤보·과충전·훑기 재사용 시계는 정상 진행한다.
  기존 표본 천체의 이동/자동 관측은 히트스톱 영향을 받지 않는 동작을 유지한다.
- 입력은 시간과 위치, 버튼 상태를 버퍼에 담아 틱 구간별로 한 번만 소비한다.
  빠르게 왕복한 경로도 보존한다. UI 위 누르기, UI 위에서 놓기, 정지/복원/포커스
  변경을 구분한다. 원/선형 관측은 천체와 커서의 상대 이동 구간으로 접촉 시간을 계산한다.
- 천체는 Godot 물리 보간, 안테나는 이전/현재 위치 보간을 사용한다. HUD, 커서,
  화면 효과와 UI 애니메이션은 렌더 프레임에서 그린다.
- 프레임당 최대 물리 단계는 8이다. 극심한 지연에서는 게임 시간이 느려질 수
  있으며, 라운드 시계만 벽시계에 맞춰 먼저 끝내지 않는다. 같은 기록 입력과
  시드의 재현성을 보장하는 범위이며 OS 입력 전달 시각 자체가 같다는 주장은 아니다.

## 자연 출현 확률

각 종류는 매 틱 서로 독립적으로 추첨한다. 한 틱에 여러 종류가 당첨될 수 있다.
아래는 연구 배율 1일 때이며 실제 확률은 `기본 확률 × 연구 배율`이다.

| 종류 | 기본 틱당 확률 | 평균 요청/초 |
|---|---:|---:|
| 일반 유성 | 0.833333% | 0.5000 |
| 고속 유성 | 0.208333% | 0.1250 |
| 분열 유성 | 0.145833% | 0.0875 |
| 발광 유성 | 0.062500% | 0.0375 |
| 인공위성 | 0.062500% | 0.0375 |
| 소행성 | 0.041667% | 0.0250 |
| 장주기 혜성 | 0.037500% | 0.0225 |
| 얼음 소행성 | 0.029167% | 0.0175 |
| 행성 | 0.016667% | 0.0100 |

해금 전에는 생성하지 않는다. 그러나 각 종류의 추첨 스트림은 동일하게
진행하므로 다른 종류 해금·등장 위치 추첨이 일반 유성의 난수열을 바꾸지 않는다.
출현 추첨과 진입 경로 난수도 종류별로 분리한다.

표본 천체는 별도 `1/(38×60)` 확률이며 고급 훑기는 `1/(30.4×60)`이다.
첫 8초 대기 이후 추첨하고, 안전한 관측 시간이 부족하면 당첨 기회 한 개만
보관한다. 해금·보상 티켓·한 번만 지급하는 계약은 그대로다.

거대 유성(시리우스), 분열 파편, 모듈 파편, 메아리, 사자자리 폭풍,
유성우와 페르세우스 돌발 유성은 자연 추첨에 포함하지 않는다. 기존 조건으로
발생하며 타이머를 고정 틱에서 진행한다. 보류한 M31 콘텐츠도 추가하지 않는다.

## 연구와 등장 공간

기존 속도 연구의 증가 곡선을 보존하기 위해 이전 간격 분포의 기대값 μ에서
`연구 배율 = 2/μ`를 구한다. L/H는 예전 1.6/2.4초에 진행도와 출현 효과를
적용한 값, f는 예전 최소 간격 보정값이다.

- f ≤ L: μ = (L+H)/2
- f ≥ H: μ = f
- 그 사이: μ = [f(f−L)+(H²−f²)/2]/(H−L)

이 값은 **확률 보정 계산용**이다. 런타임에 공유 대기 시계나 최소 출현 간격은
없다. 큰개자리/용자리 네 연구는 기본 출현 증가 한도 ×2.00/×2.35/×2.86/×4.44로
설명한다. 기존 `regular_spawn_interval_floor` 메타데이터와 getter는 보정값을
검증하는 호환 계약으로 남긴다. 화살자리 효과는 각각 확률 +5.3%/+8.7%다.

전부 해금 시 배율 1에서 총 자연 요청은 기존 0.5/초에서 0.8625/초가 된다.
이는 후기 천체를 기존 유성에 더한다는 승인된 변화다. 요청 횟수와 실제 생성,
관측 성공 및 수입은 같지 않다.

화면의 총 객체 예산 32는 대기권 22, 후기 6, 표본 3, 거대 유성 1로 나눈다.
후기는 종류마다 1자리와 공용 추가 1자리이며 한 종류 최대 2개다. 일반 자연
유성의 연구별 동시 관측 한도 4~18은 별도로 적용한다. 파편/이벤트는 자연
한도를 넘을 수 있지만 대기권 22자리 제한은 지킨다. 소멸 잔상도 자리로 센다.

예고는 등장 전에 자리를 점유하지 않는다. 도착 시 포화 상태면 최대 2초
기다리고, 지급 가능한 시간이 남지 않으면 명시적으로 예고를 해제한다.
종류별 대기열은 32개, 도착 심사 우선순위는 매 틱 순환한다. 모듈 파편은
두 자리 모두 있을 때만 쌍으로 나온다. 확률 당첨/입장/대기/만료/대기열 포화를
종류별 카운터로 구분한다. 이벤트 수량과 자연 추첨은 별도다.

## 저장과 검증

외부 저장 포맷 버전은 변경하지 않고 `spawn_model_version=2`, `simulation`
필드를 추가한다. 독립 RNG 상태는 JSON 정수 정밀도 손실을 피하기 위해 문자열로
저장한다. 진행 중 이벤트, 첫 유성 소비 여부, 폭풍 잔량, 모듈 잔여 시간과
표본 티켓을 복원한다. 일반 천체/예고는 종전처럼 복원하지 않으며 따뜻한 시작
예고를 재생하지 않는다. 옛 표본 대기 시간은 한 번의 기회로 이관한다.

이전 출현 모델의 기록은 `previous_spawn_model_record`에 보존하고 새 모델과
직접 전후 수입 비교에 쓰지 않는다. 종료 시간이 0인 저장은 라운드를 되살리지
않는다. 게임 중 저장은 틱 결과 확정 뒤 처리하지만 UI 구매 저장은 기존처럼
동기 저장과 실패 시 롤백을 유지한다.

`tests/fixed_tick_test.gd`는 30/60/144/240 FPS 일정의 실제 Game 틱 결과,
입력 왕복/버튼 경계, 히트스톱, 난수 복원, 종류별 자리와 예고 대기를 검사한다.
기존 회귀 검사와 60틱 경제 진단, Windows 내보내기도 완료 조건이다.

설계 원문과 검토 범위는 [Pro 검토 기록](history/fixed-tick-pro-review.md)에 남긴다.
