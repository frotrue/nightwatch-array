# Economy simulator and external decisions

This diagnostic runs the real main scene and `Game.simulate_tick()` at fixed
60 Hz without waiting for real-time rounds. It replaces only observation input
with a configurable instant-work adapter. Existing spawn scheduling, round
boundaries, rewards, fragments, event callbacks, research purchases, sample
draws and equipment transactions remain production code. Both base and outer
research are included; the original 95-node economy gate remains unchanged.

It never loads or writes player saves/settings. The fixture runs with save slot
zero, silent audio and no-motion presentation. No balance values are changed.

## Run one simulation

Use the Godot **editor/console binary**, not the exported game EXE. From the
project root, with `$godot` as in README:

```powershell
& $godot --headless --path . --script res://tools/economy_simulator.gd -- --config tools/economy-default.json --output build/economy-report.json
```

The output parent directory must exist. Omitting `--config` uses these defaults:

```json
{
  "seed": 42,
  "observation_chance": 0.7,
  "fragment_chance": 1.0,
  "type_chances": {},
  "quality": 0.75,
  "completion_source": "manual",
  "automatic_equipment": true,
  "strategy": "cheapest",
  "priority": [],
  "max_rounds": 300,
  "max_active_seconds": 14400,
  "purchase_limit": 0,
  "auto_draw": true,
  "auto_equip": true
}
```

- Coverage is an independent Bernoulli roll once per eligible target, not an
  exact quota and not a new roll every tick. Missed targets continue their real
  movement/expiry and may be completed by equipment when enabled. Consequently
  total completion can exceed 70%. Fragment pieces default to 100%.
- `type_chances` overrides either default, e.g. `{"major": 1, "anomaly_rare": 1}`.
  Valid types: `common`, `fast`, `fragment`, `fragment_piece`, `fireball`, `major`,
  `satellite`, `variable_star`, `binary_star`, `comet`, `galaxy`, `black_hole`,
  `anomaly_rare`. The legacy IDs mean asteroid, ice asteroid and planet.
- Anomalies wait for the real warning to finish. Fragments generated by
  completion receive work on the next tick, after value/metadata setup. No
  direct credit grant or fabricated completion signal is used.
- `completion_source` chooses manual or automatic accounting. Manual work uses
  `quality` in [0,1] and the equivalent uninterrupted tracking duration needed
  to finish. Automatic work uses the real automatic reward path.
- `automatic_equipment=false` removes ordinary dish/lane/base assist; it does
  not prevent explicitly selected automatic instant completions.
- Seeded coverage and purchase RNG streams are separate from production spawn,
  event, fragment and sample-draw streams. Same seed/config/actions reproduce
  results on the same engine/source version. Different strategies may change
  future spawn opportunities; paired seeds do not guarantee identical skies.
- `purchase_limit=0` means unlimited purchases per decision boundary. A positive
  value caps the automatic buyer only. Leave it unlimited when measuring how
  many nodes the economy actually permits: a cap can hide excessive income.
- Stops are `all_research_complete`, `round_limit`, or `active_time_limit`.
  Reaching a limit is a bounded experiment, not proof of completed progression.
  A time-limited last round is explicitly marked `partial`.

## Purchase strategies

| Strategy | Behavior |
|---|---|
| `cheapest` | Buy the cheapest legal research, recomputing after each purchase |
| `random` | Uniform choice among currently affordable research; seeded |
| `income_first` | Prefer a documented list of income nodes, otherwise cheapest; heuristic, not an optimizer |
| `priority` | Follow the configured ordered IDs; save for the first available priority if unaffordable; otherwise buy prerequisites/other cheap nodes |
| `external` | Make no autonomous purchase, draw or equipment decisions |

Automatic module handling spends affordable samples on real draws and fills
empty equipment slots in acquisition order, allowing owned duplicates. It does
not optimize builds or replace occupied slots. Disable either option to compare
research-only progression or drive equipment explicitly.

## Seed/strategy matrix

Requires Python 3.9+. Runs sequentially to avoid contention, with a per-process
wall-time limit. The output folder must be new so earlier evidence is retained.

```powershell
python tools/economy_matrix.py --godot $godot --config tools/economy-default.json --seeds 42,43,44 --strategies cheapest,income_first,random --output build/economy-matrix
```

Each run retains its exact config, JSON report and combined engine log.
`summary.csv` compares time, research counts, largest purchase batch, longest
no-purchase stretch, remaining bank and ledger reconciliation. Timeout/error
stops the matrix; a PASS-looking line cannot hide an engine/script error.

## External decisions: human or LLM

Set `strategy` to `external` (see `tools/economy-external.json`). The process
prints a state, then blocks on newline-delimited JSON from stdin while game time
is paused. Each state-changing command must supply the latest `revision`.

```json
{"action":"next_round","revision":0}
{"action":"buy","id":"better_lens","revision":1}
{"action":"state"}
{"action":"draw","revision":2}
{"action":"equip","id":"focus","slot":0,"revision":3}
{"action":"report"}
{"action":"quit"}
```

These are command examples, not a guaranteed legal purchase sequence. Drawing
requires unlocked modules and sufficient samples; equipping requires ownership
and a slot below capacity. Empty `id` unequips a slot. Rejected/stale requests do
not consume currency or advance the revision. `next_round` also means saving
the current bank and proceeding; there is no mandatory purchase count.

Responses are prefixed `SIM_JSON `, followed by an object with `kind` and
`payload`. Kinds are `state`, `result`, `round`, `report`, `error`. Ignore other
stdout lines (Godot logs). `state`/`report` are read-only commands without a
revision. `quit` or stdin EOF ends cleanly and emits the final report; an empty
line also ends the session. To automate, launch a persistent subprocess with
piped stdin/stdout, read the initial state, write one command plus newline and
flush, then read the response/new state. Do not start a new game for each action.

The decision snapshot includes revealed base research and, once the chart
expands, outer research; names, descriptions, prices, prerequisites, purchase
state, bank, sample balance, owned modules, slots, and last-round results.
It excludes hidden base nodes, internal formulas, RNG state and recommended
actions. Full diagnostic reports/configs are for the test orchestrator, not
information to feed a black-box decision agent.

## What the measurements mean

Reports include per-round income, duration, manual/automatic completion counts,
sample income, affordable frontier size, purchases and remaining bank. The
purchase timeline records each node's active time and round. `affordable_at_end`
counts the current frontier; a purchase can reveal more nodes, so it is not the
size of the entire purchasable chain. `ledger_error` should remain near zero.
The live `round` message precedes that round's purchases; the final report has
the completed purchase batches. Engine/source revision should accompany any
published measurements. LLM deliberation and UI time are not active game time.

Instant completion changes target occupancy, expiry, ordering, combo timing and
overcharge uptime. Radius, tracking speed, line geometry, slowdown and cursor
travel are not modeled as human advantages. No synthetic sky-sweep movement is
injected, so sweep-only triggers are not covered by this driver. Natural/event
spawns and completion-triggered events still run normally. It is an economy
stress model, not a realistic player completion-time estimate or an assertion
that every event occurred. Use the existing real-input probes/human play for
those questions. An LLM choosing from structured states tests understanding and
progression decisions; screenshot/mouse testing remains separate UI evidence.

## Verification

```powershell
& $godot --headless --path . --script res://tests/economy_simulator_test.gd
python tools/economy_protocol_test.py --godot $godot
```

The Godot gate is included in `tools/validate.ps1`. It covers seeded replay,
ledger conservation, rejected commands, zero coverage, production fragment
completion ordering, and outer research/draw/equipment transactions. The Python
check exercises the actual stdin/stdout protocol, including stale revisions and
EOF. Neither test asserts a desired purchasing cadence or changes prices.
