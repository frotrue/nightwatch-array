# 설정·조작·접근성 개선 계획 v1.3

2026-09-04 Agent Room `AM-EKNS`에서 Claude, Codex, Lumen이 각자 제안하고 상호 검토한 뒤 확정한 구현 기준이다. 이번 작업은 게임 규칙이나 기본 난이도를 바꾸지 않고, 기존 기능에 접근하는 경로와 피드백을 안전하게 정리한다.

## 확정 범위

1. `GameSettings`가 언어, 튜토리얼 상태, 성도 회전과 함께 전체 음량, 음소거, 전체 화면, 사용자 키 설정을 한 버전 스키마로 저장한다.
2. `project.godot`의 `nw_*` InputMap을 단일 기본값으로 삼는다. 관측 LMB와 접시 RMB는 이번 버전에서 고정한다. 성도, 메뉴/뒤로 보조키, 정산 계속 보조키, 전체 화면은 바꿀 수 있다.
3. 일시정지 중에도 동작하는 `GameInputRouter`가 모달 우선순위를 한곳에서 판정한다. 연구 성도와 엔딩 연출처럼 기존에 먼저 입력을 받아야 하는 화면은 첫 처리권을 유지한다.
4. 설정 화면에는 서로 동시에 펼쳐지지 않는 `소리 및 화면`과 `저장 관리` 섹션을 둔다. 별도 조작키 화면에서 전체 조작과 연구 선행 조건을 항상 보여 준다.
5. 설정, 조작키, 시작 슬롯, 튜토리얼의 welcome/complete 화면은 키보드 포커스와 명확한 복귀 경로를 제공한다. 실제 플레이 중 비모달 튜토리얼은 포커스를 빼앗지 않는다.
6. 키 입력 대기는 GUI보다 먼저 후보를 소비한다. `Esc`는 취소, echo와 modifier-only는 무시, 후보의 key-up까지 소비한다. 컨텍스트가 겹치는 충돌과 GUI/디버그가 선점하는 예약키는 저장 전에 거부한다.
7. 화면에 표시되는 성도 키 안내는 저장된 바인딩을 즉시 반영한다.
8. 메뉴의 선택 보조키는 다른 사용자 지정값을 잃지 않고 그 슬롯만 제거할 수 있다.

## 고정 안전장치

| 동작 | 고정 입력 | 변경 입력 | 활성 컨텍스트 |
|---|---|---|---|
| 관측/추적 | LMB | 없음 | 관측 |
| 접시 이동 | RMB | 없음 | 관측 |
| 연구 성도 | 없음 | 기본 `U` | 관측, 성도 |
| 메뉴/뒤로 | `Esc` | 선택 보조키 | 관측, 성도, 설정, 대화상자, 정산, 엔딩 |
| 정산 계속 | `Enter`, `Space` | 기본 `U` | 정산 |
| 전체 화면 | 없음 | 기본 `F11` | 전역 |

성도와 정산의 `U`는 활성 컨텍스트가 겹치지 않으므로 허용한다. 전체 화면은 전역이라 다른 변경 입력과 겹칠 수 없다. 기본값 복원은 `nw_*`만 건드리고 다른 InputMap 액션은 보존한다.

## 회의에서 수정된 안

- 전역 충돌 금지안은 컨텍스트 기반 충돌로 바꿨다. 그래야 익숙한 `U`를 성도와 정산 양쪽에서 안전하게 유지할 수 있다.
- `F11` 고정안은 전체 화면도 변경 가능하게 바꿨다. 대신 `Esc`, `Enter`, `Space`만 탈출/진행 안전키로 고정했다.
- 모든 튜토리얼 단계가 포커스를 잡는 안은 폐기했다. 일시정지 모달 단계만 포커스를 잡고 실제 조작 단계는 플레이 입력을 보존한다.
- 단순 전역 키 처리만으로는 일시정지 정산 입력이 죽고 성도 첫 처리권과 충돌했다. 항상 처리되는 라우터와 화면별 첫 처리권을 결합했다.
- 저장은 되지만 실제로 GUI나 디버그가 먼저 소비하는 키가 생길 수 있다는 검토 결과에 따라 `F9`, 현행 Ctrl+Shift 디버그 조합, Tab/방향/Home/End/Page 키를 예약했다.
- 정산 위에서 튜토리얼을 재생하면 pause 소유권이 꼬이는 교착을 발견해 버튼 비활성화와 게임 로직 가드를 함께 둔다.

## 검증 기준

- 실제 `Viewport.push_input` 경로로 paused 정산의 `U`/`Enter`/`Space`, 성도 `Esc` 우선 처리, 다음 `Esc` 설정 열기, 전체 화면, 모달 차단을 검증한다.
- 재지정 후보 press와 matching release가 다른 동작으로 새지 않고, 변경 뒤 옛 키는 멈추며 새 키만 동작해야 한다.
- 설정 테스트는 주입한 임시 경로만 사용하고, 오디오·화면·InputMap 상태를 스냅샷 후 복구한다.
- 영어와 한국어 모두 1152×648에서 설정/조작 화면을 렌더해 잘림과 포커스 표시를 확인한다.
- 전체 검증 게이트와 Windows export가 통과해야 완료로 본다.

## 다음 접근성 단계

UI 배율, 고대비/색각 프리셋, 섬광·흔들림 감소, 포인터 대체 조작, 완전한 컨트롤러 지원은 별도 설계 승인이 필요한 다음 범위다. 특히 판정 반경이나 hold 규칙을 바꾸는 옵션은 현재 게임 설계 계약에 영향을 주므로 이 문서만으로 도입하지 않는다.
